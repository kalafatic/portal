# 14. Actionable Improvement Roadmap

## 1. Roadmap Organization & Principles

This roadmap organizes engineering recommendations into four prioritized tiers:
- **P0 – Critical Defects & Security Vulnerabilities**: Must be resolved immediately before any production release.
- **P1 – Architectural Inconsistencies & Core Functional Improvements**: Fixes structural misalignment, data integrity, and access control.
- **P2 – Maintainability, Testing, and Performance**: Establishes test automation, builds hygiene, and database indexing.
- **P3 – UX Polish and Future Extensions**: Enhances user workflows, API readiness, and operational tooling.

---

## 2. Priority Item Specifications

### Milestone P0: Critical Defects & Security Hardening

#### [P0-01] Restore BCrypt Password Hashing in `UserDAO.validate`
- **Description**: Re-enable `BCrypt.checkpw` instead of plaintext string equality.
- **Current Problem**: `password.equals(hashedPassword)` fails for all BCrypt-hashed passwords generated by `resetPassword()`.
- **Evidence**: `portal-common/src/main/java/com/kalafatic/web/UserDAO.java`, line 25.
- **Proposed Solution**: Replace `return password.equals(hashedPassword);` with `return BCrypt.checkpw(password, hashedPassword);`.
- **Affected Module**: `portal-common`
- **Dependencies**: None.
- **Complexity**: Low (1 line change).
- **Risk**: Low (restores intended functionality).
- **Benefit**: Restores login capability for users with hashed passwords and eliminates insecure plaintext password validation.
- **Required Tests**: Unit tests with valid and invalid BCrypt hashes.

#### [P0-02] Implement HTTP Authentication Filter
- **Description**: Add a standard Servlet Filter to guard protected XHTML pages.
- **Current Problem**: Unauthenticated users can load `/profile.xhtml`, `/develop.xhtml`, and `/index.xhtml` directly, bypassing the login wall at the HTTP layer.
- **Evidence**: `portal-frontend/src/main/webapp/WEB-INF/web.xml` has no security filter or security constraints.
- **Proposed Solution**: Create `com.kalafatic.web.filter.AuthenticationFilter` checking session attribute `username` and redirecting anonymous users to `login.xhtml`.
- **Affected Module**: `portal-frontend`
- **Dependencies**: None.
- **Complexity**: Medium.
- **Risk**: Low.
- **Benefit**: Enforces strict perimeter security across all protected views.
- **Required Tests**: Integration tests verifying anonymous access to `profile.xhtml` returns HTTP 302 redirect.

### Milestone P1: Architectural Alignment & Data Integrity

#### [P1-01] Eliminate Phantom `LoginServlet` Declaration
- **Description**: Remove orphan `LoginServlet` declaration from backend deployment descriptor.
- **Current Problem**: `portal-backend/src/main/webapp/WEB-INF/web.xml` registers `com.kalafatic.web.LoginServlet` which does not exist in any module.
- **Evidence**: `portal-backend/src/main/webapp/WEB-INF/web.xml`, lines 5-12.
- **Proposed Solution**: Delete the legacy servlet definition or replace it with a valid servlet/forwarder if needed.
- **Affected Module**: `portal-backend`
- **Dependencies**: None.
- **Complexity**: Low.
- **Risk**: Zero.
- **Benefit**: Eliminates potential `ClassNotFoundException` during deployment.

#### [P1-02] Align JNDI Datasource Names & Clean Dormant Persistence Unit
- **Description**: Synchronize JNDI names across descriptors and clean up dormant `persistence.xml`.
- **Current Problem**: `persistence.xml` references `java:/MySqlDS`, while DAOs look up `java:jboss/datasources/MySqlDS`. `portalPU` has no JPA entities.
- **Evidence**: `portal-backend/src/main/resources/META-INF/persistence.xml` vs `UserDAO.java`.
- **Proposed Solution**: Standardize JNDI lookup to `java:jboss/datasources/MySqlDS` or convert DAOs to JPA entities managed by `portalPU`.
- **Affected Modules**: `portal-backend`, `portal-common`
- **Dependencies**: None.
- **Complexity**: Low to Medium.
- **Risk**: Low.
- **Benefit**: Resolves configuration inconsistencies and avoids confusing deployment warnings.

#### [P1-03] Create Versioned Database DDL Migrations
- **Description**: Provide automated database creation scripts (Flyway or SQL scripts).
- **Current Problem**: Repository has no DDL scripts defining the `users` and `projects` tables.
- **Evidence**: Zero `.sql` files in repository; only `datasource-config.cli` exists.
- **Proposed Solution**: Add `portal-backend/src/main/resources/schema.sql` or integrate Flyway to create `users` and `projects` tables with foreign keys and unique constraints.
- **Affected Modules**: `portal-backend`, `portal-common`
- **Dependencies**: None.
- **Complexity**: Medium.
- **Risk**: Low.
- **Benefit**: Enables reproducible automated builds and seamless environment onboarding.

### Milestone P2: Automated Testing, Performance & Build Hygiene

#### [P2-01] Implement Unit and Integration Test Suite
- **Description**: Write comprehensive unit tests for DAOs and backing beans using JUnit 4, Mockito, and H2 database.
- **Current Problem**: 0% test coverage for core business logic and controllers.
- **Evidence**: Only `ServerInstanceTest.java` exists in test packages.
- **Proposed Solution**: Add tests for `UserDAO`, `ProjectDAO`, `LoginBean`, `SidebarBean`, and `ProfileBean`.
- **Affected Modules**: `portal-common`, `portal-frontend`
- **Dependencies**: Add `mockito-core` and `h2` to `pom.xml` with `test` scope.
- **Complexity**: Medium.
- **Risk**: Low.
- **Benefit**: Prevents regressions and enables safe refactoring.

#### [P2-02] Relocate Plugin Tests & Remove Circular Test Dependencies
- **Description**: Move `ServerInstanceTest` into `portal-server-plugin/src/test`.
- **Current Problem**: Tests for `portal-server-plugin` reside inside `portal-backend` and `portal-frontend`.
- **Evidence**: `portal-backend/src/test/.../ServerInstanceTest.java` and `portal-frontend/src/test/.../ServerInstanceTest.java`.
- **Proposed Solution**: Move tests into `portal-server-plugin` and remove the `portal-server-plugin` test dependency from `portal-backend/pom.xml` and `portal-frontend/pom.xml`.
- **Affected Modules**: `portal-server-plugin`, `portal-backend`, `portal-frontend`
- **Dependencies**: None.
- **Complexity**: Low.
- **Risk**: Zero.
- **Benefit**: Establishes clean Maven separation of concerns.

#### [P2-03] Decouple Hardcoded Local User Paths from Root POM
- **Description**: Replace hardcoded `/home/petr/...` paths with configurable Maven properties or environment variables.
- **Evidence**: `portal/pom.xml`, lines 16-17.
- **Proposed Solution**: Set default paths to `${project.build.directory}/deployments` and allow overriding via `-Djboss.deploy.path=...`.
- **Affected Module**: `portal`
- **Dependencies**: None.
- **Complexity**: Low.
- **Risk**: Low.
- **Benefit**: Portability across multi-developer environments and CI/CD runners.

### Milestone P3: UX Enhancements & API Layer

#### [P3-01] Add Project URL Protocol Validation & Entity Identity
- **Description**: Add `id` field to `Project.java` and validate `url` protocol (`http://` / `https://`).
- **Proposed Solution**: Update `Project` entity with `id`, update `ProjectDAO` to delete by `id`, and add JSF validation on the URL field in `index.xhtml`.
- **Affected Modules**: `portal-common`, `portal-frontend`
- **Complexity**: Medium.
- **Benefit**: Fixes multiple-project deletion bug and eliminates potential XSS.

#### [P3-02] Implement JAX-RS REST Endpoints for System & Projects
- **Description**: Realize the aspirational architecture described in `develop.xhtml`.
- **Proposed Solution**: Implement `@Path("/api")` endpoints exposing project lists and system health in JSON format.
- **Affected Modules**: `portal-backend`, `portal-common`
- **Complexity**: High.
- **Benefit**: Opens the portal for programmatic integration and mobile clients.
